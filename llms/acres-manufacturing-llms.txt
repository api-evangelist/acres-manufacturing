# Acres Manufacturing Company

> Acres Manufacturing Company (also trading as Acres 4.0), Las Vegas, Nevada, builds Foundation — a
> casino management system that connects directly to a slot machine's SAS port and streams every
> gaming-floor event in real time. Its public developer surface is the Foundation Event Replay API,
> a WebSocket stream of SAS 6.02 exception events and meters, plus the AcresBLE iOS and Android
> Bluetooth SDKs.

Generated by API Evangelist on 2026-09-06 from the provider's own public documentation. Acres
publishes no llms.txt of its own (https://acresmanufacturing.com/llms.txt returned 404 on
2026-09-06); this file is a faithful index of what the company documents publicly, not a claim
made on its behalf.

## What Acres publishes

- Foundation Event Replay API — two WebSocket channels, real-time and historical, onto the
  Foundation event bus. 80 documented packet types, 190 documented meter names, JSON payloads.
  Host is per-property: wss://{property}.kailabor.com/nex7/sas-reader/ws/...
- AcresBLE SDKs (iOS, Android) — Bluetooth Low Energy control of card-in/card-out and slot/table
  funding and cash-out from a partner mobile app.
- No OpenAPI, AsyncAPI, GraphQL SDL, Postman collection or MCP server is published.

## How to integrate

1. Access is per casino property. There is no self-service signup, no public sandbox and no
   published key issuance — a partner is provisioned by the operator running Foundation.
2. Authentication is mutual TLS, stated on the company FAQ. The API reference itself documents no
   credential.
3. Connect a WebSocket to the property host. A request that is not upgraded to a WebSocket is
   rejected with HTTP 400.
4. Filter with sas_codes (SAS 6.02 Appendix A Table A-1 exception codes, decimal), asset_number
   and/or sas_serial_number. asset_number and sas_serial_number are OR'd when both are set.
5. Resume with idx — the monotonically increasing global ordering field on every packet. The
   real-time channel's replay cache holds at most 10,000 events or 10 minutes, whichever is
   smaller; anything older must be read from the historical channel.
6. Size the historical `limit` to how fast you consume: the provider publishes 1,000,000 packets at
   135µs/packet down to 50,000 at 6ms/packet, and warns that slower clients silently miss packets.

## Known gaps (as of 2026-09-06)

- No machine-readable contract of any kind is published.
- The documentation repository has had no commit since 2020-06-16.
- No error catalog: the only documented failure is a bare HTTP 400.
- No status page, no SLA, no deprecation policy, no changelog and no /.well-known/ documents.
- Neither SDK carries a git tag or release, so no version can be pinned.
